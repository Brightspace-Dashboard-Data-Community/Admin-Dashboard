Course Section Association (Merge)

For production merges, use Brightspace Merge Course Offering (IPSIS/SIS section associations)—not the experimental CSV tool below.

Supported workflow: Merge Course Offering

This is the same flow shown in Search → Merge Course Offering, Confirm Course Offering Merge, and the resulting classlist (multiple sections under one course shell).

  1. Search Course Offerings — Filter by Course Offering, search LMS course code/name, status Active. Find the offerings you need.
  2. Merge Course Offering — From a result row, open the menu (chevron) and choose Merge Course Offering (or add offerings into the merge list). The Before Merge column lists each selected LMS course and its current associated SIS section(s) (SIS section codes).
  3. After Merge — Choose the destination Course Offering (the shell that will keep running). Next continues the wizard.
  4. Confirm Course Offering Merge — The summary shows what IPSIS actually does, which is not generic org-structure “children” moves:
    • Create Section Associations — Associate the SIS section with the destination LMS course.
    • Remove Section Associations — Remove the association between that SIS section and the original (source) LMS course.
    • Delete Course Offerings — Remove the now-unneeded source course shell when applicable.
  5. Processing / Done — After completion, Classlist → Filter by Sections can show multiple sections (e.g. FA811 and FA813) under the destination course.

Related menu actions: Manage Course Offering Associations (review links without merging). The Org Unit Editor shows the same sections under Groups & Sections on the destination offering; the generic Children list may still be empty—that is normal.

Why the CSV tool below usually fails (Section org units). It used Valence orgstructure/…/children/ (unlink section from one course, attach under another). Brightspace returns Parents cannot be changed for Group or Section type org units — that API path is the wrong surface for IPSIS-style work. The official merge wizard updates SIS section ↔ LMS course associations and may delete the source offering; it does not rely on that orgstructure children trick. Treat the CSV runner as experimental / not supported for real merges unless D2L documents otherwise.

Experimental: CSV + orgstructure APIs

Destructive if it ever partially works. When section moves succeed, this tool would set each source course offering inactive. Use Preview only; expect 400 errors on Section org units as above.
CSV columns (header row required). Column names are case-insensitive.

Recommended (faster): use numeric org unit IDs so the tool skips code lookups.

  • MAIN_ORG_UNIT_ID — destination course offering org unit id (aliases: DESTINATION_ORG_UNIT_ID, MAIN_OU_ID)
  • SECONDARY_ORG_UNIT_ID — first source course (aliases: SOURCE_ORG_UNIT_ID, SECONDARY_OU_ID)
  • THIRD_ORG_UNIT_ID — optional second source course (alias: THIRD_OU_ID)

Alternatively (code lookup): MAIN_COURSE (destination), SECONDARY_COURSE, THIRD_COURSE — each row must identify destination and at least one source by id or code. If both id and code are present for the same role, id wins (no exactOrgUnitCode call).

Aliases supported: DESTINATION_COURSE / DestinationCourseCode for the main course; SOURCE_COURSE / SourceCourseCode for a secondary column.

APIs used: GET …/orgstructure/?exactOrgUnitCode=… (only when resolving by code), GET …/{courseId}/sections/, DELETE …/orgstructure/{source}/children/{sectionId}, POST …/orgstructure/{dest}/children/ (body: section org unit id as a JSON number per Valence), PUT …/courses/{source} with IsActive: false.

OAuth2 scopes (typical): organizations:organization:read, organizations:organization:create, organizations:organization:delete, orgunits:course:update.
