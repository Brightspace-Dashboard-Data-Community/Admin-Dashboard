Faculty Profile Widget Audit by Semester

Checks whether the Single Profile Widget is present and whether instructor name, photo, and bio have been saved (vs. default placeholders).

How to Use This Tool

Purpose

This tool audits course offerings by semester to identify:

  • Whether the Single Profile Widget is on the course homepage (HTML markers, or assumed from the shared org homepage)
  • Whether saved profile data exists via Brightspace Custom Widget Data (not Brightspace Data Sets)
  • Whether a custom name, photo, and bio/contact info have been added (vs. default placeholders)

Steps

  1. Select Semester: Choose the semester you want to audit from the dropdown
  2. Optional section filter: Limit to 8xx (online) and/or 7xx sections. Leave as “All courses” to audit every offering
  3. Click "Run Audit": The tool will check each matching course offering's homepage and widget data
  4. Review Results: The results table shows detailed information for each course
  5. Download CSV: Export the complete audit results as a CSV file

Section filter:

Course codes look like CST-133W-FA810-26/FA. The section token is the two-letter term + three digits (FA810, WI820, WN801). 8xx sections are primarily online. The filter is term-agnostic, so Fall FA8* and a future Winter WI8* / WN8* both match when you choose 8xx. Merged names such as FA820/FA830/FA840 are included if any token matches.

Report Columns:

  • OrgUnitId: The course offering's organization unit ID
  • Course Name: Full name of the course
  • Course Code: Course code/identifier
  • Has Profile Widget: Whether the Single Profile Widget is treated as present (Yes/No)
  • Has Name: Custom name saved (e.g. “Lauren Collison”) — not the default “Display Name”
  • Has Image: Uploaded photo/emoji under the widget — not the gray silhouette placeholder
  • Has Content: Custom bio/contact text (office hours, phone, email, etc.) — not “Please enter information about yourself…”
  • Display Name: The name currently stored on the widget (or the default placeholder)
  • Detection Method: How presence was determined (html_* or assumed_shared)
  • HomepageURL: Direct link to the course homepage

⚠️ Important Notes:

  • The audit may take several minutes for large semesters - watch the progress indicator
  • Courses are checked sequentially to avoid rate limits
  • If a course returns an access error, it will be marked as ERROR and the audit will continue
  • You can stop the audit at any time using the Stop button
  • Empty widget: Shows “Heading”, “Display Name”, gray silhouette, “About Me”, and the default “Please enter information about yourself…” text. Leaving the Heading as “Heading” is still considered empty for name/content — filled widgets often keep “Heading” too
  • Filled widget: Real display name, uploaded image (photo or emoji), and custom bio/contact lines (office hours, cell phone, email icon, etc.)
  • Presence: Detected from homepage HTML markers, or assumed Yes on the shared org homepage (assumed_shared)
  • Content: Read from Custom Widget Data (widgetdata) and/or Manage Files /custom_widgets/teacher_profile (especially img/ and config.txt). No saved data = empty defaults
  • If the log says widgetId is missing, paste it into PROFILE_WIDGET_ID in js/faculty-profile-audit.js from DevTools (<d2l-single-profile context="...">). The audit also caches the ID after the first course that exposes it
  • Rows highlighted in yellow indicate courses with profile widgets that are not filled in
  • After the audit completes, use the HomepageURL links to view and update profile widgets in Brightspace

Tool Interface

Optional. Matches the section in the course code or name (for example FA810 in CST-133W-FA810-26/FA).
