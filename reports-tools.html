Retirement (.retired. usernames)

Retirement here means inactivate + rename with a .retired. segment (not the same as "inactive" from long-ago logins). Use these together: retire → export or audit → reactivate when someone returns.

Retire accounts (bulk) CSV in → set Inactive and append .retired. to username.
List retired usernames Export everyone whose username contains .retired..
Audit wrong retirement pattern Match enrollment CSV to Data Hub; flag unexpected .retired. rows.
Reactivate returned retirees Compare a retired snapshot to Data Hub + API, then turn selected accounts back on.
Inactive accounts vs dormant logins

Brightspace uses "inactive" in two ways: account switched off (IsActive = false), versus still-on accounts with no login for years. Pick the report that matches what you mean.

Turned-off accounts (IsActive = no) All roles; optional filter to hide .retired. usernames.
Reactivate students (IsActive = no) Students only; fetch inactive list, select rows, bulk turn on; optional strip .retired.*.
Bulk activate from UserId CSV Headerless CSV of UserIds → set INACTIVE accounts to ACTIVE (any role).
Dormant logins (accounts still on) Students & instructors with no login for N years; accounts remain active.
