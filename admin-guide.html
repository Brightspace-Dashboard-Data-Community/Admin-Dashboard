Admin guide: what to run, and when

A working calendar for the eLearning team. Open the report from the link, run it for the current session, and act on the exceptions. Ticket lookups (Search User, Search Course, one-student activity) stay available every day and are listed separately from the scheduled scans.

Treat each session as its own term

Run the before the term and first week lists when the full semester opens and again when the second 8-week session starts. Run the end of term list when grades are due for that session. Items marked In progress are on the dashboard and still being finished — use them, and expect the page to change.

Every day the term is in session

Overnight SIS and ILP changes are the daily job. Do these before working the ticket queue so adds, drops, and missing accounts are already visible.

  • Enrollment watch list — classlist plus enrollment logs since the last successful run. This is the “what changed overnight?” scan (adds and drops, and who performed them). The first run on a course only sees people still enrolled. The next run is the one that catches overnight drops, so start it the day before you need the diff.
  • User Adds & Drops Audit (Insights) — upload the Ellucian Insights Roster Adds and Drops CSV and compare it to Brightspace. Use this when the Insights file is ready, including days the watch list already ran.
  • Recently enrolled, never logged in — students with an enroll event in the window you choose and no Brightspace system login in the last 31 days. This is the daily “new enrollments who have not signed in” list.
  • New Student Audit — when a new-students CSV arrives, check each ID against Org Defined ID and create the student accounts that are missing (role 101).
  • Cancelled Courses — compare D2L offerings to the college cancellation CSV and process CXLD courses. Run on days a new cancellation file arrives, not only at the start of the term.
  • Faculty Command Center and the Action Queue — follow up on new instructors who still have open onboarding steps. Heavier during hiring; a quick check on other days.

Before the semester starts

Work top to bottom. Shells and cancellations come first, then merges, then whether the course is actually ready for students, then the people who need accounts and roles.

  1. SIS vs D2L Course Gap — upload the SIS course list, pick the Brightspace semester, and find sections that are not course offerings yet.
  2. Course List by Semester — export the offering list you will audit against. Semester List is the reference if a term is missing from the dropdowns.
  3. Missing Start or End Dates — offerings with a blank start or end date will not behave correctly for access and for later reports.
  4. Cancelled Courses — match the college CSV and process cancellations before faculty and students land in dead shells.
  5. Course Merge Verifier, then Course Merge Updater — verifier checks course codes, Delta ID, ACTIVE/CXLD, and instructor assignment. Updater deactivates the merge courses, posts merge news, and updates the main course name. Verify before you update.
  6. Empty Course Audit — semester offerings (MERGED, CXLD, and sandboxes excluded) checked for news, content, and grade items. Upload the simplified courses CSV when you have it so start and end dates and a faculty-name fallback are on the export.
  7. Homepage Audit, Navigation Bar Audit, Content Experience Audit, and Faculty Profile Widget Audit — default homepage, default nav bar, New vs Classic content, and whether the profile widget has a real name, photo, and bio.
  8. Section Profile Config Builder — map sections to instructor profiles and publish the JSON and photos the Section Profile widget reads.
  9. Intelligent Agent Reply-To Audit — for enabled agents, find a blank or default Reply-To and pull instructor emails from the classlist before agents start sending.
  10. Role Checker — compare the faculty assignment CSV to live enrollments and bulk-fix anyone who is not Instructor on org 1001.
  11. Faculty Not Yet in Orientation, plus New Instructor Intake — instructors in active onboarding who are not in the orientation course.
  12. New Student Audit — create student accounts that exist in the new-student file and not yet in Brightspace.
  13. Provision ZZStudents — create the per-course demo accounts for the semester. This tool creates the users and does not enroll them.
  14. Copy One Module to Many Courses — only when a standard module (orientation, syllabus block, or similar) has to land in many shells before day one.
  15. Division CSV Splitter — after an audit export has a Division column, split it into one Excel file per division to send to deans.

First week

Keep the daily enrollment list running. Add these checks so empty shells, silent instructors, and students who never enter the course are caught while there is still time to fix them. Repeat this list at the start of the second 8-week session.

  • Daily items still apply: Enrollment watch list, Adds & Drops, Recently enrolled, never logged in, New Student Audit, and Cancelled Courses if a new file arrives.
  • Course Access Report — students who have not entered their courses.
  • No Instructor Activity — courses whose instructors have not accessed the course or had no activity in the last 14 days.
  • Empty Course Audit — second pass. Shells that were empty before the term and are still empty after classes start.
  • Course Merge Verifier — late merge requests that arrived after the pre-term pass. Update only after the verifier is clean.
  • Faculty Not Yet in Orientation — instructors who are teaching and still not in the orientation course.
  • Broken / Missing Links — scan the semester (or a limited set) for broken external links and missing file attachments. Start with courses already flagged by faculty.
  • Dual Enrollment Last Access — when a high-school partner asks who has entered 7xx/8xx sections. Upload Org Defined IDs, pick the semester, and skip MERGED - child offerings.
  • Enrollment Statistics — totals by role and division once the first-week roster has settled. Useful for a dean snapshot, not a daily file.

Mid-semester

Enrollment monitoring can drop from every morning to whenever a new Insights file or watch-list diff is worth reading — typically a few times a week. The midterm job is access, instructor presence, and open incompletes from the prior session.

  • No Instructor Activity — instructors who have gone quiet for 14 days.
  • Course Access Report — students who still have not entered the course.
  • Enrollment watch list and Adds & Drops — a few times a week, and any day a roster file arrives.
  • Incomplete Student Report — everyone still on the Incomplete role (role 107) in the semester. Long-running scan. Use it to see who never came back from last term’s incomplete, then change role from the report or from the Outlook tool when you are ready to email.
  • Faculty Feedback Timeliness In progress — submissions on assignments, quizzes, and discussions with late or missing feedback.
  • System Usage Analytics In progress — adoption and activity for the semester when leadership asks for a midpoint picture.
  • Enrollment Statistics — refreshed totals by role and division.
  • Dual Enrollment Last Access — partner check-in for 7xx/8xx sections.
  • Broken / Missing Links — courses reported since week one, not a full rescan unless something widespread broke.

End of semester

Run this when grades are due for the session — full term or 8-week. Grades, incompletes, and a clean snapshot of who finished are the work. Close the daily enrollment scans once rosters stop moving.

  • Grade Submission Report In progress — upload the Course Log Deep Scan CSV and get grade-submission status per course. Then Grade Submission Assessment turns that CSV into the Word assessment.
  • Incomplete Student Report — list role 107 for the semester. Follow with Incomplete Student Tool (Outlook) to change roles and open the student and instructor emails.
  • Completion Report In progress — progress-to-completion from final grades, content progress, and optional awards.
  • End of Semester Course Report In progress — one course at a time: grades, access, content, due dates, quizzes, discussions, and assignments, with next-term notes. No student names. Last-access is measured from the course end date.
  • No Instructor Activity — last pass before the grade deadline for instructors who have not been in the course.
  • Issued Awards / Badges — for a course that issues awards, confirm which students received them and when (shown in Eastern time).
  • Course Module Completion — one offering, one learner or the whole classlist, when someone asks whether topics were completed.
  • Enrollment Statistics and System Usage Analytics In progress — term snapshot for leadership.
  • MERGED Course Classlist — when Simple Syllabus needs the combined classlist from a merged offering.

Periodic and between terms

These are not morning reports. Run them on a break between sessions, when a cleanup file arrives, or when a specific request comes in. Retirement is its own sequence — do it in this order.

Retirement sequence

  1. Retire accounts (bulk) — CSV of usernames or Org Defined IDs. Sets the account inactive and appends .retired. to the username.
  2. List retired usernames — export everyone whose username contains .retired. and keep that file. The reactivation tool compares against a snapshot.
  3. Audit wrong retirement pattern — upload the semester enrollment CSV. Flags people on that list whose Brightspace username contains .retired. and should not.
  4. Reactivate returned retirees — someone who was retired and is back. Compare the retired snapshot to current data, then turn the selected accounts on.

Account cleanup

  • Dormant logins — students and instructors who are still active and have not logged in for the number of years you choose. Planning list. It does not turn accounts off.
  • Turned-off accounts — IsActive is false. Optional filter hides .retired. usernames so you can see the other inactive accounts.
  • Reactivate students — students only. Use when a student cannot sign in because the account is switched off. Optional strip of a trailing .retired. segment.
  • Bulk activate from UserId CSV — headerless list of User IDs, any role, inactive to active.
  • Deleted Users Report — usernames with a DELETED- prefix or the matching pattern, when you are cleaning leftover records.
  • Merge duplicate users — two Brightspace logins for one person. Preview enrollments, then merge awards and/or enrollments. Do this per case. It is not a semester batch, and it is not a course-section merge.
  • Never Logged In (Data Hub) — full-org extract where First Login Date is blank. Lifetime, not “enrolled this week.” Use the daily recently-enrolled report for the term. This one is for periodic cleanup.
  • Never Enrolled (1001) — users with no enrollment in that org unit, when you are reviewing stray accounts.

When someone asks

  • Watermark Adjunct Report — Org Defined ID CSV in, Username and adjunct status out, with the SEC division file.
  • Division CSV Splitter — any results file with a Division column, one workbook per division.
  • Semester Dates to CSV — date extract when another process needs semester start and end dates.
  • Enrollments Debug Report — unusual roles in one course or across a semester.
  • Course Repair Workbench — one Org Unit ID, edit the API-backed fields in one place.
  • Create a Sandbox and Sandbox Dummy Course Launcher — practice courses and the 7-week Michigan History demo. Not part of the live term rollout.

Ticket lookups (any day)

These answer one person or one course. They are not morning scans.

  • Search User — name, username, or Org Defined ID. Start here for most tickets.
  • Search Course — offering, sandbox, or org unit.
  • Enroll User and Manage Enrollment — add or fix one enrollment. Bulk Enrollment when the list is longer than a few people.
  • Learner Usage (LDAA) — last date of academic activity for one student in one course. FERPA-aware PDF. Same lookup faculty use.
  • Student Activity Log — one student, one course: assignments, quizzes, discussions, content, logins, and enrollment records Brightspace will return.
  • Access Data Lookup — one user’s system login history, or a course-access CSV.
  • System Access Log — Data Hub session CSV filtered to one Org Defined ID.
  • OrgDefinedId User Loader — validate a list of IDs and create accounts that are missing, when the file is not the standard new-student CSV.
  • Division Info — dean or division contact for a follow-up email.

Names that are easy to mix up

  • Recently enrolled, never logged in is the term check (enroll event in your window, no system login in 31 days). Never Logged In is the Data Hub lifetime extract where First Login Date is blank.
  • Course Merge Verifier / Updater combine course sections. Merge duplicate users combines two Brightspace logins. They are not interchangeable.
  • Turned-off accounts means IsActive is false. Dormant logins are still active and have not signed in for years. Retirement is inactive plus a .retired. username.
  • Enrollment watch list reads live enrollment logs and needs a prior snapshot in this browser. Adds & Drops Audit compares an Insights CSV to Brightspace. Run both during roster-change weeks.
  • Incomplete Student Report lists role 107. Incomplete Student Tool (Outlook) changes the role and opens the emails.
